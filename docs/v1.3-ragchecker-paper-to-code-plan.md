## 问题与验证目标

Agent Lab v1.2 已有 retrieval recall@5、citation、refusal 和 prompt-injection 契约，但它们不能区分检索遗漏、相关上下文噪声、无关上下文噪声、无检索支持的正确事实和幻觉。v1.3 只复现论文的 claim-level 指标计算层，并验证这些指标能否在完全合成、oracle-label 的运行中指出不同错误来源。

完成条件不是“公式能运行”，而是：严格数据契约、论文公式到代码的逐项映射、非方阵和退化输入测试、真实 `ResearchAgent` 合成运行、可重算 canonical report、首个通过结果耗时和本人方法答辩同时成立。

## 范围

### In scope

1. Overall：precision、recall、F1。
2. Retriever：claim recall、context precision。
3. Generator：context utilization、relevant/irrelevant noise sensitivity、hallucination、self-knowledge、faithfulness。
4. 使用 Python 标准库实现，不引入 NumPy 或 RAGChecker 依赖。
5. 使用显式 claim/chunk ID 与四个方向性 bool 矩阵；退化输入行为匹配所固定的官方实现。
6. 运行三个真实 `ResearchAgent` 合成案例：clean context、irrelevant noise、retrieval miss。检索排名由冻结 fixture 注入，不表述为检索器质量。

### Out of scope

- 不实现或调用 LLM claim extractor、NLI/LLM entailment checker、RefChecker、官方 benchmark 或 meta-evaluation。
- 不修改 Agent loop、CLI、Provider、Store、默认检索行为或 v1.2 suite。
- 不读取私人语料，不调用网络或真实模型，不验证论文的人类相关性结论。
- 不表述为完整 RAGChecker 复现、完整 RAG evaluator、模型质量提升或论文结论复现。

## 数据契约

每个指标输入显式包含唯一的 `ground_truth_claim_ids`、`response_claim_ids` 和 `retrieved_chunk_ids`。四个方向严格固定为：

```text
answer2response   [response_count]
response2answer   [ground_truth_count]
retrieved2answer  [ground_truth_count][chunk_count]
retrieved2response[response_count][chunk_count]
```

命名沿用官方实现：`answer2response` 表示每条 response claim 是否被 ground-truth answer 蕴含；`response2answer` 表示每条 ground-truth claim 是否被 response 蕴含。loader 拒绝未知字段、重复 ID、非严格 bool、jagged matrix 和任一维度不匹配。

当 response、ground truth 或 retrieved chunks 为空时，按官方 commit 的计算分支返回 `0.0`，不从论文公式另行推导。一个错误 response claim 同时被 relevant 与 irrelevant chunk 支持时，只计 relevant noise，避免重复归因。

## 预注册案例

`evals/paper-ragchecker-v1/suite-v1.json` 在代码实现前冻结：

1. `mixed-errors-nonsquare`：3 GT × 5 response × 2 chunks，锁定方向和全部 11 项指标；预期 precision `0.4`、recall `2/3`、F1 `0.5`、claim recall `1/3`、context precision `0.5`、context utilization `1.0`、两类 noise/hallucination/self-knowledge 各 `0.2`、faithfulness `0.6`。
2. `overlap-counts-as-relevant-noise`：同一错误 claim 同时受两类 chunk 支持，只计 relevant noise。
3. `zero-response-claims`、`zero-retrieved-chunks`、`zero-ground-truth-claims`：锁定官方退化行为。
4. `correct-but-unretrieved-self-knowledge`：区分 correctness 与 faithfulness。
5. 三个真实 Agent 案例分别预期 clean 全通过、irrelevant-noise sensitivity `0.5`、retrieval-miss recall/claim recall `0.5`。

不得根据实现输出修改 fixture、Gold 或期望值；发现预注册错误时保留失败记录、提升 suite version 后重新批准。

## 验收与停止条件

- 9 个预注册 case 的 11 项指标逐项匹配，误差不超过 `1e-12`。
- 非法 schema、矩阵方向/形状、重复 ID 和非 bool 输入 100% fail closed。
- 三个 Agent case 必须真实经过 `ResearchAgent.run()`、tool loop、claims 和 citations；直接读取期望指标不算通过。
- canonical report 必须由 runner 重算并与 committed 文件逐字节一致。
- 全量验证维持 coverage `>=90%`，默认无网络、无 Provider、无新依赖。
- 维护者本人需手算主案例，并解释双向 entailment、noise 排他、hallucination/self-knowledge 和未实现 extractor/checker 的有效性损失。答辩未完成时，代码可提交，但公开项目材料不得标记为论文理解已闭环。

## 提交与回滚

预注册文档和 fixture 先独立提交；实现、测试、canonical report、版本和包审计随后作为第二个 commit。该能力没有持久化或迁移，回退 v1.3 commit 即恢复 v1.2，不影响现有 Research Agent 行为。
