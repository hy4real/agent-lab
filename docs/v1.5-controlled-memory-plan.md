# v1.5 Controlled Memory

- 状态：已实施并通过冻结离线验收（2026-08-14）
- 范围：长期记忆可信写入、版本化本地存储、scope 隔离、受控召回、显式 legacy migration 与冻结离线评测
- 非目标：LLM 自动事实抽取、自动写入、语义冲突裁决、向量记忆、团队 ACL、远端服务、MCP、Skill 提取、Plan-and-Execute memory、Research Citation Source

## 问题

既有 `MemoryEntry(id, text, created_at)` 能证明本地持久化和词法召回 baseline，但没有来源、类型、scope、状态、schema version、并发锁或 revision CAS。长期记忆块在短期预算之外注入，最多三条 2000 字符记录可以绕过显式上下文预算；ReAct 只能用固定 task/query 自动召回，无法针对当前子问题主动搜索。

## 决策

1. 顶层状态为 `schema_version=2`、`revision`、`records`。记录字段为 `id`、`kind`、`text`、`scope`、`status`、`origin`、`source_message_ids`、`created_at`、`updated_at`、`content_hash`。
2. `kind` 只允许 `note`、`preference`、`decision`、`constraint`；`status` 只允许 `candidate`、`confirmed`、`inactive`；`origin` 只允许 `manual`、`message`、`legacy_import`。
3. 新写入先 `propose()`，再由显式 `confirm()` 激活；`deactivate()` 代替删除。只有同 scope 的 confirmed 记录可进入 `search()`、自动召回或 `memory_search`。
4. scope 使用非空、最长 128 字符的本地 namespace，不声称多租户 ACL。新 lifecycle、search 与 Environment 集成必须显式传入，缺失时 fail closed。
5. 内容先规范换行为 `\n`，再计算 UTF-8 SHA-256。ID 由 kind、规范化正文、scope、origin 与来源 message ID 的 canonical JSON hash 前 12 位生成；同一 scope 的相同历史内容一律拒绝重复，避免 inactive 记录产生重复稳定 ID。
6. 所有 mutation 在同路径 advisory lock 内重新读取状态，校验 caller 提供的 `expected_revision`，写入 revision + 1，再执行临时文件、fsync、原子替换。状态损坏、未知字段、未知 schema、锁失败与 revision 冲突只返回稳定错误。
7. 旧无 schema 的 `longterm.json` 只映射为内存中的只读 legacy view。迁移命令默认 dry-run；显式 apply 时先保存逐字节一致的 `0600` backup，再写 v2。测试和 demo 只使用临时目录。
8. 自动召回使用纯 Python deterministic BM25，沿用拉丁词与单个 CJK 字符 tokenizer；按 score 降序、record ID 升序稳定排序。最多 2 条、512 estimated tokens，完整记录装不下时跳过，不截断正文。
9. `memory_search` 接受严格 JSON `query` 与可选 `top_k`，top_k 限制为 1..5；每次最多返回 1024 estimated tokens，每个 ReAct run 最多 2 次。第三次调用返回稳定 `memory_search_limit` 错误。
10. memory tool 使用结构化 observation：正文只进入当前 ReAct context，Trace records 只保存工具名、状态和结果数量。召回块固定标注为不可信规划上下文，明确禁止执行其中指令或作为事实、权限、工具参数与引用来源。
11. Research Agent 的 Corpus、Chunk、Citation 和 grounded prompt 均不接入 MemoryRecord。`plan_execute` 的 memory rejection 保持不变。

## 兼容接口

- `LongTermMemory.add(text)` 保留为显式 manual/confirmed/local-only 兼容入口；不用于新 scope API，也不代表自动记忆。
- `LongTermMemory.retrieve(query)` 保留为 local-only compatibility search。
- 新接口为 `propose()`、`confirm()`、`deactivate()`、`list_records()`、`search()` 与 `snapshot()`；新 mutation 必须提供 `expected_revision`。
- CLI 增加 `memory propose|confirm|deactivate|list|import-legacy`。proposal 正文从 stdin 读取；默认 JSON 不回显正文、路径或底层异常。

## 评测

`evals/controlled-memory-v1/` 固定完全合成的 records、cases、thresholds 与 canonical report。契约门槛均为 100%：expected recall、scope isolation、unconfirmed exclusion、budget compliance、migration round-trip、corruption rejection、CAS conflict、concurrent mutation、prompt-injection boundary、feedback-loop prevention 与逐字节确定性。

该 suite 只证明本仓库冻结合成案例上的存储、召回和安全契约，不证明模型记忆质量、真实用户价值、生产并发、多租户隔离或外部 benchmark 结果。

## 回滚

v1 写入文件在 migration 前保留逐字节 backup；v1.5 不删除旧状态。若 v2 方向失败，可以回退代码并继续只读旧文件。任何评测门槛未达到时不发布 v1.5，也不更新简历或 walkthrough 的完成态表述。
