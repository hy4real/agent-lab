# Agent Lab v1.2 Hybrid RAG Plan

- 状态：Phase 1-5 已完成并通过离线工程验收与公开项目材料整理（2026-08-02）
- 日期：2026-08-02
- 目标：把 Agent Lab 从“词法 Evidence Research baseline”补成一个可运行、可评测、可讲述的 Hybrid RAG Agent，用于研究 RAG、向量数据库、Prompt Engineering 和检索效果优化的工程取舍
- 依据：`AGENTS.md`、`docs/v0.9-v1.1-research-agent-plan.md`、`docs/retrieval-design.md` 与本仓库的公开设计记录

## 第一性原理

岗位要求的不是依赖名词，而是一条能解释清楚的能力链：

```text
用户问题
  -> 语料 ingestion 与 chunk identity
  -> lexical/vector candidate retrieval
  -> hybrid ranking
  -> grounded prompt 与工具调用
  -> 读取原文
  -> exact citation validation
  -> 可拒答、可评测、可复现的答案
```

因此，本计划只有在向量检索真正进入 Research Agent 主链路、Prompt 有版本和对照、评测能区分 lexical 与 hybrid 时才算完成。新增接口、依赖或文档而不改变运行行为，不算补 Gap。

## 当前基线

- `Corpus`：已实现显式目录、UTF-8、大小/数量限制、no-follow 读取、source/chunk hash 和精确 span。
- lexical retrieval：已实现 CJK/Latin term-overlap baseline，默认 Research 路径实际使用它。
- hybrid retrieval：`research/retrieval.py` 已将 lexical 与 Qdrant vector 候选通过 RRF 融合，并经 `search_corpus` 接入 `ResearchAgent` 显式 hybrid 主链路；默认仍为 lexical。
- citation safety：已实现最终答案的 source/chunk/start/end/exact_text 确定性校验，必须保留。
- prompt：`baseline-v1` 与 `grounded-hybrid-v1` 已版本化并进入 run provenance；未运行真实 Provider A/B，不得声称生成质量提升。
- 评测：`research-agent-suite-v1` 保持冻结；独立 suite v2 已预注册并使用真实 FastEmbed + Qdrant 本地索引运行，canonical report 已生成并纳入本次提交。

## 范围

### In scope

1. 可选 `rag` extra：`qdrant-client>=1.18,<2`、`fastembed>=0.8,<0.9`。
2. 固定多语言 embedding 模型：`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`。
3. Qdrant local mode 向量索引、可审计 Index Manifest 和显式 rebuild。
4. lexical/vector 双路召回与 reciprocal-rank fusion；保留稳定 tie-break。
5. `ResearchAgent` 的 lexical/hybrid 检索模式切换；`search_corpus` 仍是唯一工具入口。
6. grounded Prompt Profiles：至少 baseline-v1 与 grounded-hybrid-v1，显式记录 profile、retrieval mode 和 index provenance。
7. 独立 RAG suite v2：语义改写、多文档/冲突、无答案、prompt injection、citation 和 stale index 回归。
8. public-safe 设计/实验报告与公开项目摘要；不写入外部业务或私人资料。

### Out of scope

- 不回退、删除或改写历史 commit。
- 不修改外部应用 schema，不建设个人资料 Store。
- 不读取真实外部材料、私有论文语料或其他私人资料。
- 不实现 MCP、多 Agent、Kubernetes、远端多租户、生产 SLA、真实用户产品或 vLLM/TensorRT。
- 不把单次 Provider 输出或合成语料结果表述为模型质量、用户价值或外部结果。

## 设计决策

### 1. Optional dependency boundary

默认 core、默认 CLI 和 `research-agent-suite-v1` 不加载 `qdrant-client`、`fastembed` 或模型。只有显式安装 `.[rag]` 并选择 `--retrieval hybrid` 才导入 RAG 适配层。依赖安装和首次模型下载属于独立授权动作。

### 2. Index Manifest

Manifest 至少包含：

```text
schema_version
index_version
corpus_hash
chunking: {chunk_size, overlap}
chunk_hashes
embedding_model
embedding_backend: {name, version}
embedding_probe_hash
dimension
distance
created_at
```

索引加载前必须逐项比较当前 corpus/chunk/model 配置。任何不匹配、缺字段、未知字段、索引目录损坏或向量数量不一致都 fail closed；不能静默回退到旧索引并声称使用 hybrid。

### 3. Retrieval semantics

- lexical path 使用现有 `Corpus.search()`。
- vector path 对每个 chunk 建立 point，payload 只保存稳定 chunk/source IDs 与必要的 score metadata，不保存额外私人资料。
- RRF 只融合候选排序，不把 score 当作答案置信度。
- 最终读取仍通过 `read_chunk`；citation validator 不因向量检索而放宽。
- trace 只记录 `retrieval_mode`、`index_version`、候选数、读取数、稳定错误码，不记录问题原文、prompt 或 corpus 原文。

### 4. Prompt Profiles

`baseline-v1` 保留当前最小约束；`grounded-hybrid-v1` 明确要求先检索、只依据 read_chunk、处理冲突、无证据拒答和忽略文档内指令。两者都不能绕过确定性 validator。

每次运行绑定 `prompt_profile_id`。没有固定任务集上的 baseline 对照和可解释指标改善，只能写“设计并验证 grounded prompt”，不能写“提升生成效果”。

## 分阶段执行

### Phase 1 — Documentation (completed)

只修改规范和设计文档。完成后停止，等待维护者确认代码阶段。不得安装依赖、下载模型、修改 `src/`、修改 `tests/` 或写入未经核验的外部材料。

### Phase 2 — Local vector index (completed)

新增 RAG adapter、Index Manifest、local Qdrant build/load/rebuild 命令或受控 API。先完成 stale/damaged/index mismatch 测试，再接主链路。该阶段必须独立可运行，即使 Phase 3 尚未完成。

### Phase 3 — Mainline hybrid retrieval (completed)

让 `ResearchAgent` 显式接受 retrieval mode 和 retriever factory；CLI 增加 lexical/hybrid 开关。端到端测试必须断言 search tool 实际命中 hybrid retriever；默认 lexical 行为和旧 suite 不变。

### Phase 4 — Prompt profiles and RAG suite v2 (completed)

加入 profile version、对照输出和独立 suite。先冻结 case/gold/threshold，再运行结果；不因结果不佳回调阈值。Hybrid 失败时保留失败报告，不能反向修改项目叙事。

### Phase 5 — Evidence and public material (completed)

只有前四阶段的代码、测试和报告通过后，才更新 public-safe case study；公开摘要只能引用仓库内可复核事实，不引入外部应用状态或私人资料。

## 预注册验收标准

### 工程契约

- Hybrid path 被 Research Agent 主链路真实调用：100%。
- stale/malformed/mismatched index：100% fail closed。
- citation validity：100%。
- unsupported factual claims：0。
- refusal contract：100%。
- prompt injection 不改变系统规则：100%。

### 检索效果

RAG suite v2 必须在运行前冻结 lexical-friendly、semantic rewrite、多文档冲突和拒答样例。建议门槛：

- semantic subset Hybrid recall@5 >= 0.80；
- semantic subset 相对 lexical 提升 >= 0.20；
- lexical-friendly subset 相对 lexical 不下降超过 0.10。

若当前 embedding/语料无法满足门槛，结论为 `failed_no_explainable_hybrid_gain`，不修改 gold、不降低阈值、不写“优化成功”。

### 职业材料

最终 bullet 必须同时能指向：vector index 代码、主链路调用、Prompt Profile、RAG suite 报告和边界说明。没有这些对应物，只能写当前 lexical baseline，不得提前写 RAG/向量数据库。

## 对抗式审查

| 攻击 | 失败模式 | 防线 |
| --- | --- | --- |
| 依赖堆叠 | 装 Qdrant 但主链路仍走 lexical | E2E 断言 retriever factory 和 trace mode |
| 语义假证明 | synthetic gold 被包装成泛化效果 | 独立 suite、冻结 gold、报告边界 |
| Prompt 伪优化 | 只改几句指令，没有对照 | 两个 profile + 固定任务集 + 失败也记录 |
| 索引陈旧 | corpus 变了仍复用旧向量 | manifest 全量 hash/CAS 比对，fail closed |
| 依赖污染 | 默认用户无法离线运行 | rag optional extra，v1 suite 不加载 |
| 公开叙事漂移 | 代码完成但公开说明夸大 | 产物→摘要→演示逐项人工验收 |
| 方向扩散 | 转去做 MCP、游戏、vLLM、生产部署 | 明确列为 out of scope |

## 回滚与停止条件

- Phase 1 只改文档，可直接反向提交文档变更，不触碰状态文件。
- Phase 2/3 若依赖或 index 方案不稳定，保留 lexical baseline，移除新 adapter，不改变既有 Research artifacts 或 suite。
- 若 Hybrid 在 semantic subset 没有可解释提升，停止扩展向量能力，报告失败并回到项目范围决策，不通过叙事掩盖失败。
- 若 RAG 产物无法形成可回指公开摘要的真实证据，则停止公开材料扩展，不通过叙事掩盖失败。
