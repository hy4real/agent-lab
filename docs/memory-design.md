# Short-Term Memory Design

- 状态：实施中（Run 1；2026-07-31）
- 范围：Provider 无关的短期对话记忆——消息契约、token 预算窗口、摘要触发与上下文注入
- 非目标：长期持久化（Run 2）；模型摘要能力（摘要是注入接口，模型实现不在本版）；token 精确计数（启发式）；并发、生产或外部结果结论

## 决策

1. 消息契约固定四种角色（system/user/assistant/tool），`content` 非空；消息为不可变 dataclass。
2. token 估算用确定性启发式 `ceil(chars / 4)`：保证离线可复现，文档明确不是模型 tokenizer。
3. 窗口管理采用贪心折叠：总估算超预算时，从最旧消息开始逐条折入运行摘要，直到回到预算内或只剩最近一条消息；摘要随折叠增量累积，且摘要本身计入预算（可见窗口永不排空，总估算允许略超预算，摘要长度有上限 `MAX_SUMMARY_LENGTH`）。
4. 摘要通过 `Summarizer` 协议注入：测试与 demo 使用 `DeterministicSummarizer`（截断式、逐字节可复现），生产可替换为模型实现，记忆行为不依赖具体实现。
5. 单条超预算消息保留在可见窗口（边界：不把窗口清空），在文档中显式声明。
6. 注入格式：`system` 摘要块 + 最近可见消息；调用方只消费 `inject_memory()` 的产物，不直接读内部状态。

## 验证

- 固定对话流测试覆盖：预算内全保留、超预算折叠最旧、摘要跨轮累积、注入格式、角色保持、单条超限边界、确定性（同一输入两次运行输出一致）。
- demo 使用固定虚构对话与确定性摘要器，连续两次运行逐字节一致。
- 默认离线：无 socket/HTTP、无真实 Provider、无密钥。
