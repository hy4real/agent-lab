# Evidence Research Agent v0.9-v1.1 Plan

- 状态：已实施，离线验收通过
- 批准日期：2026-08-01
- 范围：把既有 Agent 组件实验接成可运行、可评测、可交付的本地 Evidence Research Agent
- 非目标：外部业务集成、真实用户增长、业务规模化、MCP、多 Agent、Kubernetes、生产 SLA

## 第一性原理

目标岗位需要的是从问题定义到 Agent 应用交付的完整能力，不是孤立组件数量。一个可信作品必须同时证明：任务有明确输入输出；模型调用真实工具；记忆和检索影响行为；事实可验证；失败被约束；结果可重复评测；系统可安装和运行。

因此主链路固定为：

```text
explicit local corpus
  -> deterministic source/chunk identities
  -> planning and callable tools
  -> short-term trace + untrusted long-term notes
  -> grounded claims with exact citations
  -> deterministic validation
  -> evaluation and sanitized observability
```

## v0.9：端到端主链路

1. 复用并扩展既有 `ReActStrategy` 和 `AgentEnvironment`，不创建平行 Agent loop；按策略只注入必需依赖，动态 memory 是 ReAct 的唯一可变决策上下文。
2. `ToolRegistry` 注册 callable handler、参数 schema 和稳定错误；首批工具为 `list_sources`、`search_corpus`、`read_chunk`。
3. Corpus 只读取显式根目录内 `.md/.txt`，从固定 root directory fd 逐级 no-follow 打开、在同一 fd 上校验普通文件并有界读取，拒绝 symlink/path escape，并固定 source/chunk hash、span 和 exact text。
4. Research final answer 是 claims + citations 的严格结构；每条 claim 至少一个精确 Citation，无支持时返回明确拒答。
5. 短期记忆进入每轮模型输入；长期记忆只作为 untrusted notes，永不成为事实引用。
6. 默认 Replay Provider + packaged fixture；显式 `--live` 才可调用 OpenAI-compatible Provider。
7. CLI 提供 `research-demo` 与 `research`，JSON stdout 与诊断 stderr 隔离。

完成条件：固定任务真实执行 search/read 工具；memory 进入 model context；引用逐字符重算；恶意文档、未知工具、非法参数和预算耗尽均 fail closed；旧 demo 与导入保持兼容。

## v1.0：评测与可观测

冻结 `research-agent-suite-v1` 共 30 case：8 direct retrieval、8 multi-document、4 conflicting sources、4 unsupported/refusal、3 prompt injection、3 tool/budget failure。18 case 基于仓库公开设计文档的冻结副本，12 case 为完全合成对抗 fixture。Corpus digest 必须覆盖递归加载边界内的所有相对路径和文件内容，任何嵌套新增或变更都必须触发版本漂移。

确定性指标：

- citation validity = 100%
- unsupported factual claims = 0
- refusal contract = 100%
- retrieval recall@5 >= 0.90
- 稳定记录 tool status、finish reason、steps、duration 与 token usage；离线 estimate 与 live Provider 单次 measured usage 明确区分

Trace 不保存问题、prompt、原文、绝对路径、密钥或底层异常。真实模型评测只生成单独的受控报告，不参与默认验收或 suite 阈值。

检索层保留 lexical baseline，并增加注入式 Embedding Provider 与 reciprocal-rank hybrid；测试使用确定性向量，真实 embeddings 仍属于显式 live 路径。

## v1.1：工程交付

1. 可选 FastAPI/Uvicorn 服务仅包含 `GET /health` 与 `POST /v1/research`，固定 corpus root、请求不得传本地路径；本地进程只绑定 loopback，写请求校验 loopback Host、Origin 与随机 session token。
2. Docker 镜像使用非 root 用户；容器内 `0.0.0.0` 只由 ENTRYPOINT 显式开启，运行示例只映射宿主 `127.0.0.1`，build context 使用 fail-closed allowlist。
3. CI 只运行离线测试、coverage、network deny、ruff、mypy、build 和冻结成员 allowlist package audit，不读取真实密钥。
4. 清理 Git 中已追踪的 `__pycache__`、`.pyc`、`egg-info`，并由 `.gitignore` 和 package audit 阻止回归。

## 对抗式审查结论

- 关键词堆叠：所有新增能力必须被 Research 主链路真实调用；否则不进入本计划。
- 与其他个人应用重复：Agent Lab 不读取外部应用的资料、状态或本地 Store。
- Synthetic 假证明：评测同时使用仓库真实公开设计文档和对抗 fixture；仍不表述真实用户或模型质量。
- Memory 污染：长期记忆不能作为 Citation Source，模型不能自动写入。
- Prompt injection：语料只作为 untrusted data，最终答案由确定性 Citation validator 审核。
- Runtime 重复：只扩展 `AgentEnvironment`/`ReActStrategy`，Research 层是 facade 而非第二运行时。
- 范围失控：三个版本独立可验收；MCP、多 Agent、Kubernetes 明确排除。
- 岗位偏差：只覆盖通用/后端 Agent 应用研发；不声称覆盖终端客户端方向。

## 实施结果

- v0.9：既有 `AgentEnvironment`/`ReActStrategy` 已接入 callable research tools、动态短期记忆、不可信长期笔记与精确 citation validator。
- v1.0：`research-agent-suite-v1` 的 suite/corpus digest 冻结；30/30 case 通过，四项确定性门槛全部满足。
- v1.1：CLI、固定 corpus 的 loopback API、非 root Dockerfile、离线 CI、Hatch 构建边界和 package audit 已实现。
- `$check` 修复：递归 corpus digest、ReAct 单一动态上下文、策略依赖校验、live 稳定错误边界与单次 measured usage 已纳入回归验证。
- 本地验收覆盖真实 loopback HTTP；Docker daemon 未运行，因此未执行本机 image build。未运行 live Provider、外部网络、发布或部署。
- Public-safe 工程 case study 已整理为 `docs/evidence-research-agent-case-study.md`，只引用仓库内可复核事实，并明确不外推模型、生产、用户或外部结果。
